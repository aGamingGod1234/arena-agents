# Generality suite

`scenarios-train.json` contains 28 revision-2 fixtures with five-to-ten-minute windows. Private evaluation definitions, descriptions and traces belong only in the research evaluator-only directory, outside the product repository and fixer notes. Both runner and setup validator require `--expect-fixture-sha256` for private fixtures and refuse byte drift before launch. Private outputs must remain beneath their private definition directory.

Fixtures record seed, dimension, spawn or deterministic locator, inventory, armour, effects, weather, time, objective and deadline. Small declared resource patches sit in natural biomes, caves and structures. Legacy scenarios and their setup lifecycle remain unchanged. Generality setup suppresses command feedback before player mode changes. Chunk readiness and actual biome/footing are checked. Hunger is applied until a food-level receipt reaches the target. Construction holds a grounded creative player; survival is restored and fresh observations allowed before goal translation. Natural regeneration stays off until the first gameplay decision. Fire, flood, fall and lava fixtures explicitly warn of impending hazards, which activate after that decision. Timed hazard effects begin with the hazard. Mobs stay frozen until the first decision. The observer stops a run and invalidates measurement if captured provider inputs expose setup feedback, evaluator commands, fixture metadata or creative setup state.

Use the pinned arm format in `scripts/quality/README.md`. Source/JAR pins are checked before launch and before each worker. Single-arm runs permit the original stack without first-response capture; paired arms require capture hooks. The judge reads actions, starting facts, changes in player condition, death events and completion claims/checks. It does not receive raw model inputs, outcome summaries, arm identity, fixture commands or overall success flags.

```powershell
node scripts/quality/run-generality.mjs --arms arms.json --arm paired --scenarios T01,T02,T03 --runs 3 --concurrency 3 --port-base 26900 --out RESULTS --java JDK/bin/java.exe --server-template TEMPLATE --max-total-cost-usd 5
node scripts/quality/run-generality.mjs --arms arms.json --arm B --scenarios T01,T02,T03 --runs 1 --concurrency 3 --port-base 26900 --out SMOKE
node scripts/quality/run-generality.mjs --arms arms.json --split heldout --fixtures PRIVATE/scenarios-heldout.json --expect-fixture-sha256 EXPECTED_64_HEX --arm paired --runs 3 --concurrency 3 --port-base 26900 --out PRIVATE/results
```

Whole pairs occupy one worker slot. AB/BA order alternates across scenarios and repetitions. Slots have disjoint ten-port blocks; concurrency is bounded at four and the block must be explicitly supplied. Parallel results are descriptive comparisons. Checkpoints retain worker failures. `--max-total-cost-usd` sets the ledger admission budget (`--max-play-cost-usd` is an alias). Strict execution supports the exact locally compiled dragon goal with a Claude player and finite total cap. Auxiliary goal translation, voice and live judges are disabled; success comes from the game. Unsupported goals refuse before launch. `--codex-observer-cap yes` enables the broader fixture/judge workflow with estimates that may exceed both a reservation and the ledger cap.

The general train fixtures above need auxiliary translation: add `--codex-observer-cap yes` only when possible overruns are acceptable. Use `run-long.mjs` without that flag for the strict beat-the-game run. Strict reports mark model judgments deferred and never call them; no unbounded post-run grading is launched automatically.

The default judge family differs from the play family: Codex Sol judges Claude arms and Claude Opus judges Codex arms, at medium effort. Provider, model, effort and executable remain configurable. Two calls see the same evidence in opposite order, independently. Numeric scores need an action timestamp; synthetic/start/claim rows alone are insufficient. Recovery that was not exercised is null and excluded from means and agreement. Agreement reports the number of comparable dimensions, repeatability and per-dimension differences; it does not establish validity.

Objective markers combine RCON samples and terminal bridge facts. Survival reports no death over the actual played window; a survival goal predicate additionally requires verified completion, so idle timeouts are not objective success. Other markers include predicates, first progress, deaths/causes, repeated failures, blind moves after path failures, unrevisited placed stations, idle gaps, calls, tokens and spend. Idle accounting ends at objective success. Shelter requires supported solid roofing, walls and evidence of successful player placement; leaves are excluded and roof heights two through four are supported. Unknown evidence remains null. Waste measures remain proxies, particularly idle gaps and abandoned stations. Some runs are invalid: they have an observer error (including `EVALUATOR_INPUT_LEAK`), no valid goal window, or a spend-cap stop. They are excluded from the success, survival, judge, waste and other means. Each category reports their number as `invalid`, and `summary.invalidRuns` lists the reasons.

Setup validation uses no model calls. Start a disposable evaluator-owned server with the fixture seed, Carpet, RCON and reserved ports; never point this tool at an owner's world. It creates a fresh fake player per fixture, waits for readiness, checks safe preparation and pending-decision holds, activates hazards, verifies conditions and cleans up its players. Its output contains commands and must remain private for private fixtures.

```powershell
node scripts/quality/validate-generality-fixtures.mjs --fixtures scripts/quality/scenarios-train.json --rcon-port 26901 --password-file PRIVATE_PASSWORD_FILE --out TRAIN_SETUP.json
powershell -File scripts/quality/launch-scenarios.ps1 -ProjectRoot PROJECT -ArgumentsFile ARGUMENTS.json -Runner run-generality.mjs -JobDirectory NEW_JOB_DIR
node scripts/quality/reextract-generality.mjs RESULTS/results.json NEW_EXTRACTED_DIR
```

The hidden launcher survives SSH disconnect and writes status/logs to disk. Re-extraction calls no provider and preserves historical judgments; those judgments must not be interpreted as having used a newer rubric. `complete` means attempts were collected, not that every scenario or measurement succeeded. Inspect measurement status, leakage errors, objective coverage and judge errors.
