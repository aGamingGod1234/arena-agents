## How often guards existed and how quickly they acted

The frozen protocol retains **20:33:58.459–21:14:09.558**, not the full game's observation prefix. Of 6,064 living observations, 5,858 (96.6%) had a guard installed. Of 644 observations containing threats, **629 (97.7%) had a guard**, but only **43 (6.7%) had any guard condition true**. There were no condition-evaluation errors in those threat samples. These are sample counts, not independent encounters or time-weighted success rates.

The unrotated coordinator installation/deletion trace spans the earlier game too. It records **23 firings**, all followed by a matching guard-owned command: activation-to-dispatch median **80 ms**, maximum **119 ms**. Only four first commands were mob defenses (three fights, one flee); the others addressed terrain or air. Across 1,570 dispatched actions, dispatch preparation median was **2.9 ms**, p95 **14.0 ms**, maximum **101.1 ms**. Selected danger wakes reached provider submission in **24–66 ms**. The two measured first model flee choices took **4.014 and 4.233 seconds**. None of the three terminal danger windows received a guard defense.

The hypothesis is therefore partly right: waiting for inference is too slow. The primary cause is **incomplete authored conditions and missing in-source continuation**, hidden by a lexical “covers hazards” status. Guard installation alone was already common. The traces do not justify changing wake scheduling, model-defense precedence or body movement.

## Implementation

- Wake guard status now states installed / last condition true, false, unchecked or error / firing count. It no longer infers protection from hazard words appearing in source. Missing-guard wakes near observed threats add an act-now, then-author reminder.
- Always-loaded guidance puts guard authorship while safe before exposed work, explains the fuse/turn mismatch, includes targetable threats behind the player, asks the model to inspect all threats and write the next defense after failed/stopped actions in the same source, and replaces guards by id without a deletion gap.
- Remaining complete guard examples moved out of model-facing control reference into test fixtures. There is no supplied defense program to copy, no new saved/named routine, no automatic guard installation, and no new mod action. Existing legacy API compatibility remains; the allowed player path is live source.
- Installation traces now retain guard kind, source origin and the authored condition for future audits. Existing source hashes remain.
