# Snow navigation investigation

Evidence comes from `arena-feel-run/trials/after-3/sol/`. These are log reconstructions and Java geometry reproductions, not a replay of the saved world. The retained protocol starts late; earlier geometry comes from the full provider capture. Observation rows do not record every navigation read or every underground block, so missing cells below are identified as unknown by reproducing the sight rule, not asserted to have been logged as unknown.

## Changes and safety

Acquired-terrain sight treats only the requested support block's own **one-layer, zero-collision coating** as a surface coating for that ray. Other intervening snow, opaque blocks and leaves still occlude. Navigation reads and classifies the actual backing cell, so a floating dusting does not manufacture a floor, and powder snow, magma, lava and water cannot become dry safe footing. Ordinary visible-block observation rays are unchanged.

Air clearance now samples the lower interior as well as the centre/top. There is no proximity-based grant of unseen cells: every new sample passes both the view cone and the existing obstruction/lava checks. Nearby cells behind the player remain unknown. Existing bounded frontier continuation can use the newly acquired support and headroom without changing the model's destination.

An additional geometry audit found a movement defect independent of the logged one-layer cases: from two-layer snow at Y64 (physical feet Y64.125, grid node Y65) to a full block beside it (feet Y65, also grid Y65), the old planner selected WALK. The **0.875-block rise** exceeds vanilla's 0.6 step height, so the motor never jumped. Same-row edges now use physical support heights and request JUMP_UP when needed, with the existing jump-rise and clearance checks. The jump fast path reads the landing's actual support row. Shallow snow rises remain walking steps.

Vanilla 26.1.2's `SnowLayerBlock.getCollisionShape` uses `(layers - 1)/8`, including **7/8** for eight-layer snow, despite its full visual outline. Tests use those actual shapes; a snow block has full collision. Grass, fern, leaf litter and short plants already have empty collision and needed no allowlist change. Leaves retain solid collision.

## Verification

`SnowNavigationVerification` exercises production sight, cell classification, the pathfinder and the motor's jump decision. It covers all eight snow layer counts, snow blocks, covered ground, one-block banks, fractional rises, low steps, foliage, occlusion, unseen nearby cells and unsafe footing. Existing core navigation/perception checks also run through `verifyCore`.

Final Java check: `JAVA_HOME=/usr/lib/jvm/temurin-25-jdk-amd64 flock /tmp/aa/gradle.lock ./gradlew verifyCore --offline` passed with **2,555,107 protocol/core assertions**, including **48 new snow-navigation assertions**. The initial covered-ground regression failed before the changes; the one-block-bank regression also failed with only the dusting fix in place, isolating the headroom sampling defect.

Coordinator contracts: **598 passed**. Full coordinator suite: **6,528 tests; 6,442 passed, 12 failed, 74 skipped**. Eleven failures are the documented Linux/Windows baseline. The extra inherited `native sequence stops before later actions after an unverified near stop` test requires `durationMs: 0`; it received 1 ms in the suite and 3 ms in isolation. Coordinator files are unchanged. No same-seed live Minecraft trial was run, so these tests establish the reproduced geometry fixes, not a measured live success-rate increase.
